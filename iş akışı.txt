Görev işlemlerinin ortak geçiş yolu

1. todo.facade.ts → this.todoApi üzerinden HTTP isteği hazırlanır; firstValueFrom(...) veya subscribe() isteği başlatır.
2. apiErrorInterceptor → authInterceptor; sendWithToken(...) Authorization: Bearer başlığını ekler.
3. Access token yoksa veya korunan istek 401 dönerse auth.refreshSession() ile yenileme denenir.
4. Program.cs → UseSecurityHeaders → UseSerilogRequestLogging → Production ortamında UseHsts / UseHttpsRedirection → UseExceptionHandler → UseCors → UseRateLimiter → UseAuthentication → UseAuthorization.
5. Authentication JWT'yi doğrular; [Authorize] bulunan controller için giriş yapılmış olması gerekir.
6. Controller → ilgili use case'in ExecuteAsync(...) metodu çağrılır.
7. Decorator sırası: LoggingDecorator → ExpectedErrorDecorator → ValidationDecorator → ilgili use case'in HandleAsync(...) metodu.
8. Sonuç decorator'lardan geri döner → ToActionResult(...) HTTP cevabını oluşturur → frontend interceptor'ları → facade → ekran.

12. Bu liste istekleri de ortak interceptor, middleware ve decorator yolundan geçer.


Hata dönüşü

1. Validation, erişim veya domain kuralı başarısızsa normal başarı yoluna devam edilmez.
2. Result hataları ToActionResult(...) ile; beklenmeyen exception'lar API exception handler'larıyla HTTP hatasına çevrilir.
3. api-error.interceptor.ts → errors.normalize(error) → todo.facade.ts içindeki showError(...) → facade.error() üzerinden hata ekranda gösterilir.
